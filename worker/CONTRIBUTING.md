# Contributing

Useful contributions include reviewed problem statements and transcriptions,
small certificate verifiers, agent/harness adapters, reproducible experiments and
tests exposing false claims. Add regression coverage for changes to acceptance,
storage, limits or retry behavior.

Run `python3 -m unittest discover -s tests -v`. Docker and real Witness CLI tests
are opt-in and use disposable databases. No paid provider is required for the
default suite. Never include credentials, private config, personal memory,
proprietary datasets or unreviewed generated research as facts.

Do not weaken a verifier to accept a candidate. New sources need attribution,
review date, hash, rights review and current reward/eligibility conditions. A
price on a web page is not escrowed funding. Negative search is not impossibility.

Discuss target/verifier changes before broad rewrites. Automatic outreach, paper
submission, prize claims, posts and paid API calls are outside contribution scope.
Contributors remain responsible for authorship, licenses and accurate claims.

## Fair credit and collective awards

The project owner's governing principle is fair, balanced treatment and named
credit for every accepted contributing party to a collective result. Names are
presented with equal prominence in a neutral order. Every party's actual work is
retained in the contribution record, including useful attempts and verification.

Equal award shares are the starting proposal. If contributions differ materially,
a revised split can be proposed under the allocation procedure agreed before the
work. Show each proposed share in a chart together with links to the accepted work
and reasons for the adjustment. An AI score, model choice, agent count, token use,
lines of code or claimed hours must not automatically determine financial shares.
Technical records support contributor review; they do not settle what is fair.

The procedure must identify independent reviewers, disclose conflicts of interest,
give affected contributors a chance to challenge a proposal, and record agreement
or unresolved disputes before finalizing a split. No operator may silently change
the rules or award themselves a larger share. Retain versioned proposals and
decisions. An unresolved allocation is pending, not an approved payment.

Each party needs one stable registered contributor ID and a chosen public credited
name, agreed before participation. Their agents and individual submissions link
to that ID. Several agents belonging to one party do not create several shares.
Do not publish private legal names or contact details without that party's consent.

Before inviting contributors to a problem, publish consistent criteria for an
accepted contribution, the covered award pool, the contributor-registration and
dispute process, allocation procedure and rounding rules. Reproducible attempts,
useful negative coverage, source corrections, implementations and independent
verification can qualify under those published criteria. Preserve who contributed,
what was accepted, and which later work used it; do not silently remove a party
from a result's credit record. A report remains unverified until checked, and
unsolicited spam does not become accepted research merely by being submitted.

These are the intended project rules, recorded before a public contributor pilot.
The current worker does not implement contributor registration, award custody or
automated payments. External award conditions must be checked before advertising
a shared award; this policy does not represent an award organizer's agreement.
